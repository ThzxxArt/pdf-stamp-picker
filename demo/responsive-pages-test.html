测试页自身窄视口可用性（套件 ⑰）

以 370px 宽（手机竖屏量级）真实加载代表页，每页检查三件事：①实载内容是否横向溢出 ②注入 64 位 hash 长串后容器是否还能断行（带正控）③是否有 viewport meta。

②为什么要注入：历史缺陷是"日志里打印 64 位 hash → 窄屏被顶破"，但被测页在被量那一刻日志里未必正好有长串，所以"直接量页面当前溢不溢出"实测对 5 个代表页一次都不会红（把 harness 的断行规则整条摘掉也照样全绿 = 假通过）。改成注入真实长串后，同样的变异立刻报红 4 页（117~169px）。

②的正控：注入后先把探针强制 nowrap 测一次，必须撑破（证明这个探针本来一定会溢），再按页面真实样式测一次要求不撑破。若正控不撑破了，说明断言已失去张力 → 直接判失败，而不是继续显示绿色。

背景：此前所有测试页都没有 viewport meta，也没有窄屏样式 —— 用手机打开 run-all 或任一测试页时， 浏览器按 980px 虚拟宽度布局再整体缩略，长 hash 又把日志撑出屏幕。被测库的窄容器自适应做了， 装它的测试页自己却没人管。本套件就是盯这件事的。长文本容器名单取自 __TEST.LONG_TEXT_SEL（与 harness 注入的样式规则同源），不另抄一份。
